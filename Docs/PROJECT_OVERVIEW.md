# Multicam Partner Portal - Project Overview

## What This Portal Replaces

This Django-based portal replaces **3,000+ Google Sheets** used to manage the Multicam Partner Program:

- **38 First Article (FA) workbooks** - One per partner, tracking fabric/camouflage approval submissions
- **38 Lot Acceptance workbooks** - One per partner, tracking production lot submissions
- **Manual email workflows** - Notifications now automated
- **Scattered data** - Now centralized in one database

### Directory Descriptions

| Directory | Purpose |
|-----------|---------|
| **`config/`** | Django settings, root URL routing, WSGI/ASGI configs. Contains `settings.py` with environment-specific configuration (dev/prod). |
| **`accounts/`** | User authentication, `UserProfile` model extending Django's User with roles (partner, inspector, staff), decorators for role-based access, login/logout views. |
| **`inspections/`** | Core business logic: `FirstArticleInspection` and `LotAcceptance` models, submission forms, review queues, evaluation models (`FAEvaluation`, `LotEvaluation`), email notification triggers. |
| **`notifications/`** | `Notification` model for logging all notifications, `NotificationService` for sending email/in-app, context processor for unread counts, notification list/dropdown views. |
| **`dashboard/`** | Dashboard views for each role: Partner sees submissions/stats, Inspectors see review queues, Staff sees high-level analytics. Routes users to correct dashboard. |
| **`core/`** | Public-facing pages (home, about, contact), shared models (`CamouflageType`, `VariantColor`), management commands for data loading. |
| **`approvals/`** | Reserved for future approval workflow extensions (currently minimal). |
| **`templates/`** | Jinja2/Django HTML templates organized by app. Uses Tailwind CSS + Flowbite components. `base.html` provides site-wide layout with sidebar. |
| **`static/`** | Custom static files (admin CSS fixes). Most styling comes from Tailwind CDN. |
| **`staticfiles/`** | Generated by `collectstatic` for production. Gitignored. |
| **`media/`** | User-uploaded files (FA/Lot documents). Gitignored. |
| **`Docs/`** | Project documentation: this file, DEVELOPMENT.md, DEPLOYMENT.md. |

## MVP User Roles

| Role | Code | Description |
|------|------|-------------|
| **Partner** | `user_functionality='partner'` | Submits First Articles and Lots |
| **Primary Inspector** | `user_functionality='admin'`, `admin_role='primary_inspector'` | First FA review + all Lot reviews |
| **Final Inspector** | `user_functionality='admin'`, `admin_role='final_inspector'` | Final FA review only |
| **Staff** | `user_functionality='admin'`, `admin_role='staff_executive'` etc. | Dashboard access (executive/finance/operations) |
| **Full Admin** | `user_functionality='admin'`, `admin_role='full_admin'` | All access |

### Role Checking in Code

```python
profile = request.user.profile
profile.is_partner()           # Partner user
profile.is_primary_inspector() # Primary Inspector
profile.is_final_inspector()   # Final Inspector
profile.is_any_inspector()     # Any inspector type
profile.is_staff()             # Staff (executive/finance/operations)
```

## Workflows

### Two-Stage First Article (FA) Workflow

```
┌─────────────────────┐
│ Partner Submits FA  │
│   status: pending   │
└──────────┬──────────┘
           │
           ▼
    ┌──────────────────────────┐
    │ Primary Inspector Review │
    └──────┬───────────────┬───┘
           │               │
    APPROVE│               │REJECT
           │               │
           ▼               ▼
┌──────────────────┐  ┌────────────────┐
│ status:          │  │ status:        │
│ pending_final    │  │ rejected       │
└────────┬─────────┘  └───────┬────────┘
         │                     │
         ▼                     │
┌────────────────────────┐    │
│ Final Inspector Review │    │
└──────┬─────────────┬───┘    │
       │             │         │
APPROVE│             │REJECT   │
       │             │         │
       ▼             ▼         ▼
┌──────────┐  ┌────────────────────────┐
│ status:  │  │ Partner Notified       │
│ approved │  │ (+ Primary if final)   │
└────┬─────┘  └──────────┬─────────────┘
     │                   │
     │                   │
     ▼                   ▼
┌────────────────┐  ┌───────────────┐
│ Partner Can    │  │ Can Resubmit  │
│ Submit Lots    │  │ (loops back)  │
└────────────────┘  └───────────────┘
```

**FA Status Values:**
- `pending` - Awaiting Primary Inspector review
- `pending_final` - Primary approved, awaiting Final Inspector review
- `approved` - Fully approved by both inspectors
- `rejected` - Rejected by either inspector

### Single-Stage Lot Workflow

```
┌────────────────────────┐
│ Partner has Approved   │
│ FA (prerequisite)      │
└───────────┬────────────┘
            │
            ▼
┌────────────────────────┐
│ Partner Submits Lot    │
│   status: pending      │
└───────────┬────────────┘
            │
            ▼
┌────────────────────────────┐
│ Primary Inspector Review   │
│ (single stage)             │
└────────┬───────────────┬───┘
         │               │
  APPROVE│               │REJECT
         │               │
         ▼               ▼
┌────────────────┐  ┌────────────────┐
│ status:        │  │ status:        │
│ approved       │  │ rejected       │
└───────┬────────┘  └────────┬───────┘
        │                    │
        ▼                    ▼
┌────────────────┐  ┌────────────────────┐
│ Partner        │  │ Partner Notified   │
│ Notified       │  │ Can Resubmit       │
└────────────────┘  └──────────┬─────────┘
                               │
                               └──► (loops back to submit)
```

**Requirements:**
- Partner must have at least one **approved** FA before submitting Lots
- Lot dropdown only shows approved FAs belonging to that partner
- Primary Inspector handles all Lot reviews (Final Inspector has no Lot responsibilities)

## Display Name Convention

All First Articles and Lots use a consistent display format:

**First Article:** `{fabric_style} - {multicam_variant} - {fa_lot_number}`
- Example: `131968 Nylon/Spandex - Multicam - 10008840229`

**Lot:** `{fabric_style} - {multicam_variant} - {lot_lot_number}`
- Example: `131968 Nylon/Spandex - Multicam - 10010043849`

### Field Naming Clarification
- `fa_lot_number` - The First Article's lot number (on FirstArticleInspection model)
- `lot_lot_number` - The Lot's own lot number (on LotAcceptance model)
- `original_fa_lot_number` - Copied from FA's `fa_lot_number` when a Lot is submitted

This `display_name` property is used in all lists, headers, and review screens. The internal IDs (`fai_id`, `lot_id`) are auto-generated as `{COMPANY}-FA-{sequence}` and `{COMPANY}-LOT-{sequence}`.

## Key Models

### UserProfile (`accounts/models.py`)

Extends Django's User model with:
- `company_name` - Partner company name
- `user_functionality` - Role type (`partner` or `admin`)
- `admin_role` - Sub-role for admins (`primary_inspector`, `final_inspector`, `staff_*`, `full_admin`)
- `status` - Account status (`active`, `inactive`, `pending`)

### FirstArticleInspection (`inspections/models.py`)

- `fai_id` - Auto-generated primary key
- `vendor` - ForeignKey to UserProfile (the partner)
- `fabric_style` - Free text, main identifier
- `multicam_variant` - ForeignKey to CamouflageType
- `fa_lot_number` - The First Article's lot number
- `status` - Workflow status (pending/pending_final/approved/rejected)
- `is_historic` - Boolean for legacy imports (admin-only)
- Primary Inspector evaluation fields (`primary_*`)
- Final Inspector evaluation fields (`final_*`)

### LotAcceptance (`inspections/models.py`)

- `lot_id` - Auto-generated primary key
- `vendor` - ForeignKey to UserProfile
- `original_fa` - **ForeignKey to FirstArticleInspection** (must be approved)
- `fabric_style` - Copied from FA on submission
- `original_fa_lot_number` - Copied from FA's `fa_lot_number`
- `lot_lot_number` - The Lot's own lot number
- `status` - Workflow status (pending/approved/rejected)
- Single-stage inspector evaluation fields

### Notification (`notifications/models.py`)

- `recipient` - ForeignKey to User
- `channel` - `email` or `in_app`
- `notification_type` - Event type (fa_submitted, lot_approved, etc.)
- `title`, `message` - Notification content
- `status` - `pending`, `sent`, `failed`, `read`
- `email_to`, `email_subject` - Email-specific fields
- `action_url` - Link to related resource
- `content_type`, `object_id` - GenericForeignKey to related object

## Historic First Articles

The `is_historic` field on FirstArticleInspection is for **legacy data imports**:

- Only admins can set `is_historic = True`
- Historic FAs may have missing fields that would normally be required
- Display "N/A - Historic First Article" for missing data
- Used when importing data from the old Google Sheets system
